# 变量审查：装备与穿着槽位一致性核验

审查阶段固定为：补齐 → 修正（包含装备与穿着槽位核验）→ 智能精简 → 最终复核。默认策略详细列出检查项目；核心规则要求每次执行，不因自定义策略而跳过。程序在准备上下文时扫描当前主角及本次社交范围NPC，向同一次AI请求提供可核实的归位命令组和待确认线索，不增加AI请求。

## 按现有结构检查

- 主角：`角色.装备`，使用现有头部、胸部、盔甲、内衬、腿部、手部、足部、主武器、副武器、暗器、背部、腰部、坐骑。
- NPC：`社交[i].当前装备`，使用现有主武器、副武器、服装、饰品、内衣、内裤、袜饰、鞋履。
- 旧档中实际存在的额外键也参与检查，例如腰带。归位目标必须属于相应现有schema，保留旧键为空，不进行存档迁移。

确定性检查优先结合独立的装备位置、类型和描述；不以可能被污染的`当前装备部位`自证正确。不根据性别限制槽位。日常短袖、常规鞋履、项链等明确类型可提出归位；类型与位置相矛盾、目标被占用、名称对应多个实体、无法核实用途或特殊规则时保留为待确认。

连衣裙、连体衣、披风、腰封、特殊护甲、多槽装备以及旧档自带的特殊规则，不能按普通单槽物品强行移动。相似名字、甚至同名不同ID的两件物品不合并。重复引用只有能通过稳定实体及唯一名称映射核实，才允许移除错误槽位引用。主角背包中装备实体与装备栏引用并非两份库存，不删除背包条目。

## 归位保护

1. 候选使用现有set命令：先写空闲目标槽，再把错误原槽设为“无”。同一实体已正确占据目标时，仅清空已证明重复的错误引用。
2. Validation核验完整命令组。缺一半、引用不同、重复写同一字段、整栏替换/删除、同批改写对应人物背包或属性均不能借归位例外执行。
3. 确定归位可以通过原装备移除保护；其它装备请求仍经原保护。正文明确且主体、物品可核实的换装继续兼容旧格式装备记录。
4. 纯归位跳过会自动穿戴、补物品或去重的规范化，仅同步已有主角物品的当前装备引用。其它业务变更仍走原路径。
5. Simulation额外比对整组命令、所有装备引用及背包资产；除了当前装备引用外，物品属性和数量不得变化。失败时相关人物命令整体回退，不能只应用一半。
6. 归位始终是“修正”，不是垃圾清理。既有低价值整理也不能删除仍被装备引用的物品。fingerprint、实际Diff、Preview确认、应用前重新校验及Safe Apply保持原流程。

## Streaming

沿用现有协议与同一次SSE请求，原Modal的候选卡片显示“修正建议 · 装备槽位 · 人物名”、变量路径、真实当前值、建议值和依据。待确认项保持待确认分类。候选阶段不能写变量；完整响应后按程序最终校验和实际Diff展示，确认后才保存。
